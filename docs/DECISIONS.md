| 7 | 2026-10-28 | Turnstile generator (program decision 48) | Separate project and image in `generator/`: no database access, no backend imports; Pydantic models generated from `backend/openapi.json` (datamodel-code-generator) behind a thin httpx client, drift-checked in CI | It plays the external face-ID turnstile system and integrates exactly like a real gate would |
| 8 | 2026-10-28 | Python projects | Two independent uv projects (`backend/`, `generator/`) instead of one uv workspace | Nothing is shared by design (decision 7); separate locks keep the two images independent. Deviates from the program brief's "uv workspace" wording on purpose |
| 9 | 2026-10-28 | Backend modules | `core`, `registry`, `ingestion`, `occupancy`, `realtime`, `reports`, `jobs`; router → service → repository inside each | Organized by feature, with HTTP, domain and storage layers kept apart |
| 10 | 2026-10-28 | Ingestion transport | `POST /api/v1/events`: JSON batch of 1 to 1000 `GateEvent` items, 202 with per-item outcome; no broker | About 2k events a day; idempotent retries make HTTP enough |
| 11 | 2026-10-28 | Idempotency | `event_id` primary key plus a payload hash: same id and hash is a duplicate, same id with a different hash is rejected `event_id_conflict`; the generator derives ids with uuid5 from the event content | Safe retries and reruns; conflicting resends are visible |
| 12 | 2026-10-28 | Event-time bounds | Accept events up to 120 days old and 300 s in the future; older is rejected `too_old`, later `in_future` | Covers the 90-day backfill plus a month of margin and catches bad gate clocks |
| 13 | 2026-10-28 | Backpressure | 429 `ingest-busy` with `Retry-After` when 4 batches are in flight per process or the lot lock times out (2 s); 503 with `Retry-After` while draining or with the database down | Protects the connection pool; clients know when to retry |
| 14 | 2026-10-28 | Occupancy model | Stays re-derived per (lot, student, service day) from all its events on every batch; the change in open stays is applied to `lot_occupancy`; the stored count is exact and clamped only on output | Correct in any arrival order and under duplicates, with no full scans |
| 15 | 2026-10-28 | Never-closed entries | `close_day` sets open stays of a past day to `closed_by_reconciliation` at local midnight, recounts and records drift; late data reopens the day | Deterministic and idempotent end-of-day reconciliation with run metadata |
| 16 | 2026-10-28 | Real-time channel | WebSocket `/api/v1/live/availability`, a full availability snapshot per message | Built into browsers and React Native (Expo Go needs no polyfill, unlike SSE); one typed message |
| 17 | 2026-10-28 | Real-time fan-out | Each API process polls `lot_occupancy` versions every second and sends a heartbeat snapshot every 15 s | Sees writes from every replica and the worker, needs no extra connection, testable on SQLite |
| 18 | 2026-10-28 | Auth | Three API keys in `X-API-Key`: ingest (gates, generator), admin (registry writes), operator (web operator view); public read routes anonymous | Least privilege per holder; the browser-held operator key cannot write the registry or inject events. JWT would add a user store for one role |
| 19 | 2026-10-28 | Registry | Admin `PUT` by natural key for lots and gates, bulk upsert for students, no deletes; a gate's lot and direction are immutable once it exists (row 32) | Idempotent bootstrap; append-only events stay referentially valid |
| 20 | 2026-10-28 | Lot capacity history | Effective-dated `lot_capacity_history`; current capacity computed at read time; `dim_lot` SCD2 built from it | Business-time history; dbt snapshots would record when dbt ran, not when capacity changed |
| 21 | 2026-10-28 | Batch runner | `pipeline_runs` is the job queue; the worker claims with `FOR UPDATE SKIP LOCKED`; operator endpoints only enqueue; a scheduler in the worker enqueues the 15-minute warehouse refresh and the daily close | One run log, restart-safe, no Airflow |
| 22 | 2026-10-28 | Ingestion health | Per-batch `ingest_batches` rows and `gates.last_*` columns written in the ingest transaction | Cheap operator health view and run metadata for ingestion |
| 23 | 2026-10-28 | Raw archive | Daily Parquet per service date for events and rejects, contract check before publishing, atomic directory swap | Raw lake copy that is safe to re-run |
| 24 | 2026-10-28 | Analytics store (program decision 44) | dbt-postgres warehouse (`warehouse_staging` views, `warehouse` dims, facts and marts) in the same Postgres; DuckDB dropped | One analytics store; the reports API reads only the marts |
| 25 | 2026-10-28 | dbt incremental strategy | delete+insert by `event_id` for events and by (lot, service date) partitions for stays and occupancy snapshots | Late data rebuilds whole partitions with no orphan rows |
| 26 | 2026-10-28 | Occupancy snapshots | `fct_occupancy_snapshot` (lot × 15-min slot) derived in dbt from stays | Backfillable, recomputed for late events, exact peaks and minutes at full capacity |
| 27 | 2026-10-28 | Tests | Unit, API and worker tests on SQLite (aiosqlite); Postgres-only behavior behind an `integration` marker (CI service container; locally the compose Postgres); 85% coverage gate per Python project | The default suite needs no Docker |
| 28 | 2026-10-28 | Time zone | `America/Fortaleza` defines the service date | São Luís local day, no daylight saving |
| 29 | 2026-10-28 | Client stack versions | Expo SDK 57 (React Native 0.86.3, React 19.2.3 pinned in both apps with npm `overrides`), TypeScript 5.9, Node 24 LTS | SDK 58's Expo Go is not in the stores yet; openapi-typescript 7 needs TypeScript 5; one React copy in the workspace |
| 30 | 2026-10-28 | JS workspace | npm workspaces (`apps/web`, `apps/mobile`, `packages/api-client`) | Expo needs no hoisting tweaks with npm; matches the other portfolio repos |
| 31 | 2026-10-28 | Charts | ECharts on web; hand-drawn `react-native-svg` charts on mobile | Matches vaccine-warehouse; react-native-svg ships with Expo Go |
| 32 | 2026-10-28 | Gate immutability | A gate's `lot_id` and `direction` cannot change from creation (409 `gate-immutable`); only the name can | Simpler than checking for events, and safe because append-only events reference both. Refines decision 19, which tied the rule to the gate having events |
| 33 | 2026-10-28 | Counter version and freshness | `lot_occupancy.version` rises by 1 for every lot with at least one newly accepted event in a batch (even when occupied does not change); `last_event_at` on lots and gates never moves backwards; `gates.last_*` also count duplicates, since a resend shows the gate is alive | Simple rule the live poller can rely on; no event is lost to a late arrival that rewinds a timestamp |
| 34 | 2026-10-28 | Lot counter row | `lot_occupancy` rows are created by the registry lot upsert (insert-ignore on every PUT) and backfilled by migration 0002; the ingest lock step also creates a missing row | One row per lot is the invariant the row lock and the recount rely on |
| 35 | 2026-10-28 | Operator read shapes | `per_minute` lists only minutes that had a batch; the rejects cursor is an opaque keyset on (received_at, reject_id); the `ingest_rejects(received_at)` index is a plain b-tree scanned backwards, not DESC | Sparse series are enough for a chart; a plain index avoids migration drift checks on expression indexes |
| 36 | 2026-10-28 | Generated model flags | `datamodel-codegen` 0.87.0 (pinned) with `--use-annotated --field-constraints --enum-field-as-literal all --use-union-operator --use-standard-collections --disable-timestamp --formatters black isort`; the Makefile holds the one command, `make lint` regenerates into a temp file and diffs | Output is deterministic and mypy-clean without overrides; no timestamp header means no spurious drift |
| 37 | 2026-10-28 | Generator HTTP style | Synchronous httpx client, one process, injected sleeper and clock; 401/403/422 exit 2, give-up after 10 attempts exits 1 | A batch loop gains nothing from asyncio; injection makes retry and live loops testable without sleeping |
| 38 | 2026-10-28 | Synthetic calendar | Holidays are an approximate 2026 list of national and São Luís dates in `demand.py` (factor 0.1), not an official calendar; the semester start (2026-08-03) is an assumption, settable with `GENERATOR_SEMESTER_START`, and the week before it runs at 0.25 | Gives the reports realistic dips with no external data; the dbt holidays seed (PR 7) mirrors the constant |
| 39 | 2026-10-28 | Generator demand model | Arrivals are Poisson per minute from a three-peak curve (07:15, 13:00, 18:15) times day, scenario and rate factors; each lot has its own slice of the students, so nobody is in two lots at once; the capacity history comes from the API, so backfills follow the registry | Deterministic per (seed, lot, date); cars turned away at full capacity create minutes at full |
| 40 | 2026-10-28 | Generator e2e in CI | Job `generator-e2e` runs the real API on Postgres with ephemeral masked keys, bootstrap, a 7-day backfill twice (any 7-day window gives well over 1500 events, unlike 2 days on a weekend or holiday), and `scripts/e2e_check.py`, which reads Postgres directly (a test, not the generator) | Proves the contract end to end: counts, duplicates on rerun, occupancy equals open stays, only injected rejects |
| 41 | 2026-10-28 | Socket refusal | A connection over the cap, or arriving while the process drains, is accepted and then closed with 1013 or 1001 | Closing before accept is an HTTP 403 that clients cannot tell from an auth failure; the close code is what the reconnect policy reads |
| 42 | 2026-10-28 | Poller failure pace | A failing tick is logged with the exception type only and retried after interval x 2^failures, capped at 30 s; the shutdown waits at most 2 s for sockets to leave. uvicorn closes websockets with 1012 before the lifespan shutdown runs, so `DrainingServer.shutdown()` closes the hub (1001) first and the lifespan repeats it harmlessly for TestClient and non-CLI runs | The poller must never die silently or hammer a database that is down; a stuck socket must not hold the shutdown |
| 43 | 2026-10-28 | Enqueue and the past-date rule | `POST /operator/runs` answers 422 for a `service_date` that is not before today (service time zone) and 409 `run-already-active` when the same job and date is queued or running; the job itself still refuses an open day with `day-not-closed` (409 problem, exit code 2 on the CLI) | The request shape is a validation error the operator can fix; the job guard protects the CLI and any path that skips the API |
| 44 | 2026-10-28 | Reopened days | `service_days.exported_events` holds the number of gate_events rows the last successful export took (NULL until one succeeds); `daily` closes again every past date in the 120-day event age window whose stored event count differs from it, or is NULL. Late events for a closed day are paired with `day_closed=True` at that day's cutoff, so they never reopen an open stay; `closed_at` is kept for display and the `late_events` metric only | `received_at` is stamped before the lot lock and `closed_at` before the reconcile locks, so no timestamp comparison can be right; gate_events is append-only, so a count is exact, and a failed export leaves the date pending |
| 45 | 2026-10-28 | Archive layout details | Rejects are partitioned by the local received date (`raw/ingest_rejects/received_date=`), not by service date, because a reject may have none; the manifest adds `rows_sha256` (hash of the rows in event order) next to the file `sha256`, and a rerun compares `rows_sha256`; the `export` command is a `close_day` run with `mode = 'export'` because `job` has no export value | Deterministic reruns that do not depend on Parquet writer bytes; no schema change for a CLI convenience |
| 46 | 2026-10-28 | Shape of `daily` | One parent run; a child `close_day` run per pending date in date order: yesterday, past dates with events that were never closed, reopened dates, and the date the run was requested for; a failing child fails the parent after the other days ran; a date whose `close_day` is already queued or running is skipped and listed in the metrics; the scheduler enqueues one `daily` per date whatever its status, so a failed one is re-queued by an operator, not in a loop. `warehouse` stays reserved in the `job` check until the warehouse PR | Backfilled history closes in one pass and one bad day does not block the rest; no retry storm against a persistent failure |
| 47 | 2026-10-28 | Worker process rules | `--once` and the CLI commands run the job in-process as a recorded run (no queue hop); the startup sweep marks every `running` row failed `abandoned` because there is one worker per database; on SIGTERM the current run gets 25 s, then it is cancelled and recorded failed `interrupted`; `PARKING_WORKER_METRICS_PORT=0` turns the exporter off and `PARKING_WORKER_HEARTBEAT_FILE` moves the heartbeat file | Restart-safe with the Docker HEALTHCHECK contract of the plan; testable on Windows |
| 48 | 2026-10-28 | Archive swap | Two directory renames (partition to `.old`, temp to partition), retried briefly on `PermissionError` because Windows refuses to rename a directory a reader holds open; a reader sees the old partition, no partition for a moment, or the new one | Same code on Linux and Windows; no half-written partition is ever visible |
| 49 | 2026-10-28 | Known limitation: late rejects in the archive | `daily` picks dates to re-export by the gate_events count only (row 44), so a reject that commits after the export snapshot of its received date stays out of that day's `raw/ingest_rejects` partition until an operator re-runs the export (`mode = export`; the new `rows_sha256` makes it rewrite the partition). No code change | The daily run starts 30 minutes after the local day ends, so a reject would have to commit more than 30 minutes after it was stamped; counting rejects per received date as well would add a column and a query for a case that should not occur |
